# figma-use

MCP resource: `skill://figma/figma-use/SKILL.md`

Read when the task needs JavaScript execution through `use_figma` or through `figma-repl-mcp` tools that execute Figma Plugin API code, including Figma canvas writes, node creation or editing, variable/style work, or unique programmatic inspection.

Escalate specialized work before calling tools:

- Full page, full screen, multi-section layout, modal, drawer, sidebar, or panel work also reads [figma-generate-design.md](figma-generate-design.md).
- Creating any production-quality component also reads [figma-generate-library.md](figma-generate-library.md).
- Design-system component, variable, style, or token work starts from the official `figma-use` working-with-design-systems reference selected by that skill.
- FigJam boards also read [figma-use-figjam.md](figma-use-figjam.md).
- Slides files also read [figma-use-slides.md](figma-use-slides.md).

Required before tool call: read the `figma-use` skill or this MCP resource before every `use_figma` call. When using the MCP resource route, pass `skillNames: "resource:figma-use"` unless another loaded Figma skill instructs otherwise.

Also read this before `figma_repl_run_script_file`, `figma_repl_eval`, `figma_repl_inspect`, and `figma_repl_validate_handles`: those calls still execute upstream `use_figma` Plugin API JavaScript, even though the local `figma-repl-mcp` server adds batching, file-based `.figma.js` script execution, handles, helper functions, `$.select`, `$.cloneNodeTree`, `$.imageAsset`, `$.screenshot`, dry-run previews, output files, safety diagnostics, upstream delegation, and compact docs/API lookup. Prefer `figma_repl_init_workspace` once, then `figma_repl_prepare_task` plus `figma_repl_run_script_file` with `inputFile`/`outputFile` names for non-trivial Plugin API work; keep each transaction below upstream `use_figma` code payload limits and split dense work into skeleton, asset-target, upload-fill, and visual-fix scripts when needed; `helperProfile` defaults to `auto` and injects heavier helpers only when the script source uses them; use `$.imageAsset({ base64, parent, size, position, as })` for small generated PNG/JPEG assets; for large generated assets, create named target rectangles in `.figma.js` and use `figma_repl_apply_asset_manifest` with inline `assets` or `manifestPath`, passing explicit upstream `toolName`/`argumentsTemplate` when the upload/fill schema is not known; `figma_repl_apply_asset_manifest` validates target image fills when upstream eval is available; use `$.screenshot(target)` or `node.screenshot()` only as an opportunistic inline check and use `figma_repl_capture_node` to write final visual QA, including upstream screenshot URL payloads and compact QA metadata, to a local file; use `figma_repl_run_task_plan` for repeatable local plans that combine script dry-runs/execution, asset manifests, screenshot captures, and generic upstream tool calls, with default step output files in initialized workspaces; use `$.select` instead of direct `figma.currentPage.selection`; use `$.cloneNodeTree({ source, placement: "right" })` for side-by-side copy workflows that should preserve instance subtrees; use raw `figma_repl_eval` for small advanced cases after checking diagnostics. Start with `figma_repl_capabilities` or resources such as `figma-repl://file-workflow`, `figma-repl://workflow-tools`, `figma-repl://api-cards`, `figma-repl://intents`, `figma-repl://scripts`, `figma-repl://safety`, `figma-repl://docs`, and `figma-repl://api` when the needed script helper, Plugin API symbol, or facade routing boundary is unclear. Use `figma_repl_api_card` and `figma_repl_suggest_api` before broader lookup when the task intent is common. Use `figma_repl_call_upstream_tool` for official upstream Figma MCP capabilities not covered by the file workflow. If direct `figma_repl_*` tools are unavailable because the plugin is not installed in the active Codex environment, use package-local `createFigmaReplClient` as the expected fallback. REPL handles are in-process node-id aliases, not persistent JS variables or durable storage.

Local plugin reference: prefer `figma_repl_docs_search` and `figma_repl_api_lookup` for capped snippets with file/line evidence before reading reference files directly. If direct reading is still needed, read only the specific referenced files needed by the `figma-use` skill. For exact Plugin API symbols, use [plugin-api-lookup.md](plugin-api-lookup.md) and do not dump the full declaration file.
